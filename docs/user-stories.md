# 評論產品 User Stories

術語依 `CONTEXT.md`。已定案決策見文末「Implementation Decisions」；ADR 見 `docs/adr/`。

## 應用層

0. 作為操作員，我想為每個產品建立一個應用（系統產生應用 key），以便各產品的留言與設定互相隔離。
0a. 作為操作員，我想在控制台操作前先選應用，以便所有搜尋、審核、封鎖與設定只作用於該應用。
0b. 作為操作員，我想查看應用列表，以便在多個產品之間切換。
0c. 作為操作員，我想為應用改名，以便產品演進時顯示名稱保持準確。
0d. 作為操作員，我想停用一個應用，以便下架產品的評論區熄滅而資料保留。
0e. 作為操作員，我想建立應用時設定一個 URL 友善的 slug（全系統唯一、建立後不可改），以便 URL 可以選擇性帶有人類可讀的應用識別前綴。
0f. 作為登入用戶，我想每則留言都有單一全球唯一 ID（生成時即唯一、經 API 暴露），以便前端零組合 logic 就能為每則留言生成 canonical URL，留言可以像文章一樣被分享與索引。

## 前端（網頁／App）

### 閱讀

1. 作為登入用戶，我想在文章頁看到該文章的主評論列表（預設熱度行先、無限捲動），以便看到最有共鳴的討論。
1a. 作為登入用戶，我想切換主評論列表的排序方式（最相關＝熱度降序／最新行先／最舊行先），以便用我偏好的方式瀏覽評論。
1a. 作為登入用戶，我想切換主評論列表的排序方式（最相關＝熱度降序／最新行先／最舊行先），以便用我偏好的方式瀏覽評論。
2. 作為登入用戶，我想在主評論上看到分支內的評論數，以便決定要不要點開分支。
3. 作為登入用戶，我想點開主評論查看分支內容（最舊在前、超過一頁時分支內無限捲動），以便閱讀完整對話。
4. 作為登入用戶，我想在每則留言上看到作者的暱稱與頭像，以便辨識留言者。
5. 作為登入用戶，我想在每則留言上看到各 emoji 的總數，以便感受留言的共鳴程度。
6. 作為登入用戶，我想看到自己待審中的留言（標示「審核中」），以便知道留言已送出、正在等審核。
7. 作為登入用戶，我想看到自己被拒的留言（標示「未通過審核」），以便知道留言沒有通過審核。
8. 作為登入用戶，我想看到被操作員刪除的主評論顯示為「此留言已被 01 管理員刪除」佔位（回覆保留），以便理解對話脈絡。
9. 作為登入用戶，我想在未登入時完全看不到評論區，以便（產品面）所有互動都有可追責身份。
9a. 作為登入用戶，我想一次過批次取多篇文章的頭幾則評論及總評論數（上限 N 篇 x M 則），以便在文章列表頁預覽各篇的評論活躍度而不壓垮系統。

### 留言

10. 作為登入用戶，我想在文章下發表主評論（純文字、上限 1000 字、允許換行），以便參與討論。
11. 作為登入用戶，我想在主評論的分支內回覆（不指名對象、不開新層、按時間順序），以便與他人對話。
12. 作為登入用戶，我想在留言間隔未到時收到明確錯誤（含剩餘等待時間），以便知道何時能再留言。
13. 作為登入用戶，我想在每日額度用盡時收到明確錯誤（含今日剩餘額度），以便知道額度已用完。
14. 作為登入用戶，我想在留言命中敏感字時看到留言進入待審（僅自己可見），以便知道內容需要人工審核。
14a. 作為登入用戶，我想在一般封鎖／完全封鎖狀態下留言時收到「你的帳號已被限制留言」，以便知道帳號被限制。
14b. 作為被自動封禁的用戶，我想收到明確訊息表示我因被檢舉而暫時被限制留言，以便知道為何不能留言。

### emoji 與三連

15. 作為登入用戶，我想對已發佈留言按 emoji（笑／哭／加油，每人每則每 emoji 一次），以便表達感受。
16. 作為登入用戶，我想取消自己給過的 emoji（再點一次扣回），以便反悔。
17. 用戶可以給自己的留言按 emoji（無限制）。
18. 作為登入用戶，我想一鍵三連（三個 emoji 各給一次，每則限一次），以便快速表達強烈共鳴。
19. 作為登入用戶，我想在用過三連後看到按鈕變灰，以便知道這則已三連過。

### 需求原文對照

20. 作為登入用戶，我想靜音另一用戶（其所有留言含未來的都對我隱藏、可解除、對方無感知），以便過濾不想看到的內容。
21. 作為登入用戶，我想解除靜音，以便恢復看到該用戶的留言。
21a. 作為登入用戶，我想檢舉單則留言（檢舉後該則對我永遠隱藏、數量不限），以便隱藏有問題的單則留言而不必靜音整個用戶。
21b. 作為操作員，我想查看檢舉紀錄（哪個用戶被檢舉幾次、誰檢舉的、檢舉哪則留言），以便透過群眾訊號發現有問題的用戶或內容。
21c. 作為操作員，我想查看自動封禁狀態與原因（觸發哪個 tier、檢舉數、犯規累計次數），以便複核並在誤判時手動解封。
21d. 作為操作員，我想設定自動封禁的 tier 門檻（各 tier 檢舉數）與封禁時長，以便根據 spam 模式調校系統。
22. 作為登入用戶，我想在完全封鎖的用戶視角下完全看不到評論區，以便（產品面）完全封鎖是徹底隔離。

## 控制台

### 登入與權限

23. 作為操作員，我想用內部授權系統登入控制台，以便使用全部管理功能。
24. 作為操作員，登入即擁有全部功能（單一權限），以便不需要權限管理。

### 搜尋

25. 作為操作員，我想用關鍵字搜尋所有評論，以便找到特定內容。
26. 作為操作員，我想用時間範圍搜尋評論，以便縮小範圍。
27. 作為操作員，我想用文章 key 搜尋評論，以便處理特定文章的留言。
28. 作為操作員，我想按狀態篩選（待審／已發佈／已刪），以便分別處理不同狀態的留言。
28a. 作為操作員，我想在搜尋結果中直接刪除留言，以便快速處理違規內容。
28b. 作為操作員，我想批次刪除指定文章 key 下的所有留言，以便快速清理有問題文章的評論區。
28c. 作為操作員，我想批次刪除指定用戶的所有留言，以便一次過移除 spammer 的全部足跡。
28b. 作為操作員，我想搜尋用戶（會員 ID 為主、暱稱為輔），以便從用戶出發管理。
28c. 作為操作員，我想查看用戶的留言數據（總數、狀態分佈、近 30 天每日量、最近留言時間、帳號狀態），以便評估是否封鎖。

### 審核

29. 作為操作員，我想看待審列表並批准或拒絕，以便完成人審。
30. 作為操作員，我想管理自訂敏感字（加入／移除，同步到內容審核服務），以便補充機審詞庫。
31. 作為操作員，我想查看審計紀錄（誰在何時刪了哪則、封了誰、敏感字異動），以便追溯操作。

### 封鎖與系統管理

32. 作為操作員，我想對用戶施加一般封鎖（可看、不能留言），以便限制輕微違規者。
33. 作為操作員，我想對用戶施加完全封鎖（不能看、不能留言），以便隔離嚴重違規者。
34. 作為操作員，我想手動解封用戶，以便修正誤封。
35. 作為操作員，我想設定所選應用的留言間隔，以便控制該應用的留言頻率。
36. 作為操作員，我想設定所選應用的每日留言上限，以便控制該應用的留言總量。
36a. 作為操作員，我想設定新用戶冷卻期（註冊後多久內不能留言），以便防止 spammer 註冊後即灌水。
37. 作為操作員，我想查看封鎖狀態（一般／完全／正常），以便掌握用戶狀態。

### 行動場景

38. 作為操作員，我想在手機瀏覽器使用控制台（響應式網頁，免裝 App），以便通勤時找不到桌面電腦也能操作。
39. 作為操作員，我想在手機上以一指完成待審留言的批准／拒絕（審核流程以行動體驗為第一優先），以便隨時隨地清待審佇列。
40. 作為操作員，我想在手機上使用搜尋、封鎖、系統管理等功能（響應式可用、不追求行動最佳化），以便不在電腦前也能處理急事。

## Out of Scope（v1 不做）

- 置頂留言、官方／認證標籤、單篇文章關閉留言
- 通知（回覆通知、審核結果通知）
- 用戶自刪／自編輯留言
- 嵌入式 widget／SDK（API 優先，各端自建 UI）
- 操作員帳號管理（沿用內部授權系統）
- 誤刪復原（審計留痕，無還原按鈕）
- 即時推送（他人新留言需重新整理）
- 針對個別用戶覆寫間隔／額度
- 待審留言超時自動批准／自動拒絕（留言等待人審，行動版控制台即為延遲解法）
- 控制台原生 App／PWA（響應式網頁已覆蓋行動場景）
- 跨應用聯合封鎖（一次封全部應用）
- 應用刪除（資料永久保留，只可停用）
- 應用 slug 修改（建立後不可改，URL 穩定性優先）
- 應用層級的操作員權限差異（單一權限，所有操作員可管理所有應用）

## Implementation Decisions

- 應用層：一個產品一個應用，key resources 按應用分開——留言（文章 key 只在應用內唯一）、emoji、靜音、檢舉、自動封禁（犯規累計按應用計）、封鎖、敏感字、系統設定、審計紀錄；用戶與操作員跨應用共用，但各應用內狀態互相獨立；封鎖不跨應用（ADR-0009）
- 所有 API（前端＋控制台）必帶應用 key；控制台操作前先選應用；資料表加 application_id，unique constraint 改複合鍵；Redis 快取與批次端點以應用為範圍
- 應用由控制台建立、系統產生應用 key；可改名、可停用（停用＝前端 API 一律 404、資料保留）；不可刪除
- 識別字：應用 key＝機器識別字（系統產生、API 呼叫用）；應用 slug＝公開識別字（操作員建立時設定、小寫英數字＋連字號、全系統唯一、建立後不可改），角色是可選的 URL 前綴、不參與唯一性；留言 ID＝生成時即全球唯一的 ULID，經 API 暴露，前端以此單一 ID 構造留言 canonical URL（URL 長相由前端自定，評論系統不擁有 URL）；存取仍以應用 key 為範圍（跨應用查 → 404）
- 兩層結構＋分支內扁平（@ 對象）；主評論最新在前、分支內最舊在前；cursor 分頁；無限捲動（主列表與分支內皆是）
- 文章 key＝呼叫方提供的任意字串（建議 UUID），在單一應用內唯一，評論系統不管理文章
- emoji 固定 3 個（笑／哭／加油）；每 emoji 每人每則一次、可取消；三連＝三個全給的快捷、每則一次；只顯示數字不顯示誰按
- 靜音：用戶級、可解除、被靜音者零感知；顯示會員暱稱＋頭像
- 未登入完全不可見（ADR-0003）
- 用戶不可刪不可編自己的留言（ADR-0002）
- 機審採網易雲盾 SaaS，自訂詞同步到雲盾自訂詞庫（ADR-0001，整合細節待補）
- 先審後發；操作員刪主評論→留「此留言已被 01 管理員刪除」佔位、回覆保留；支援批次刪除（按文章 key、按用戶）
- 封鎖：無期限、可手動解封；兩種模式都不隱藏既有留言（ADR-0004）；被拒時回明確訊息
- 檢舉：用戶對單則留言檢舉，檢舉後該則對檢舉者永遠隱藏、數量不限；控制台可見檢舉紀錄
- 自動封禁：用戶被檢舉達 tier 門檻即自動封禁，採累計犯規升級模型（第 1 次 tier 1 封 1 天、第 2 次 tier 2 封 1 週、第 3 次 tier 3 封 1 個月、第 4 次永久封禁）；tier 1-3 為一般封鎖，永久封禁為完全封鎖；門檻由控制台設定（預設 5/10/20，24 小時滾動窗口計算）；操作員可見狀態與原因、可手動解封；審計紀錄記「系統自動封禁」
- 額度：送出即計（待審、被拒都算）；間隔從上次送出起算；日界 UTC+8；按應用設定單一值。新用戶冷卻期：註冊後 N 時間內不能留言，N 按應用由控制台設定
- 留言內容：純文字、上限 1000 字、允許換行、URL 當普通文字
- 控制台搜尋：關鍵字／時間／文章 key／狀態；搜尋結果可直接刪；用戶搜尋以會員 ID 為主、暱稱為輔（會員系統提供查詢介面）
- 控制台操作前先選應用，所有搜尋、審核、封鎖與設定以所選應用為範圍
- 審計紀錄：刪除／封鎖／敏感字異動記操作人＋時間；UI 只做列表
- 前端會員系統與控制台內部授權是兩套獨立系統；操作員帳號沿用內部授權系統
- 控制台為響應式網頁：手機瀏覽器完整可用，審核（待審批准／拒絕）以行動體驗為第一優先設計，其餘功能響應式可用即可
