# 評論產品 User Stories

術語依 `CONTEXT.md`。已定案決策見文末「Implementation Decisions」；ADR 見 `docs/adr/`。

## 前端（網頁／App）

### 閱讀

1. 作為登入用戶，我想在文章頁看到該文章的主評論列表（最新在前、無限捲動），以便掌握最新討論。
2. 作為登入用戶，我想在主評論上看到分支內的評論數，以便決定要不要點開分支。
3. 作為登入用戶，我想點開主評論查看分支內容（最舊在前、超過一頁時分支內無限捲動），以便閱讀完整對話。
4. 作為登入用戶，我想在每則留言上看到作者的暱稱與頭像，以便辨識留言者。
5. 作為登入用戶，我想在每則留言上看到各 emoji 的總數，以便感受留言的共鳴程度。
6. 作為登入用戶，我想看到自己待審中的留言（標示「審核中」），以便知道留言已送出、正在等審核。
7. 作為登入用戶，我想看到自己被拒的留言（標示「未通過審核」），以便知道留言沒有通過審核。
8. 作為登入用戶，我想看到被操作員刪除的主評論顯示為「已刪除」佔位（回覆保留），以便理解對話脈絡。
9. 作為登入用戶，我想在未登入時完全看不到評論區，以便（產品面）所有互動都有可追責身份。

### 留言

10. 作為登入用戶，我想在文章下發表主評論（純文字、上限 1000 字、允許換行），以便參與討論。
11. 作為登入用戶，我想在主評論的分支內回覆（可指名 @ 對象，不開新層），以便與他人對話。
12. 作為登入用戶，我想在留言間隔未到時收到明確錯誤（含剩餘等待時間），以便知道何時能再留言。
13. 作為登入用戶，我想在每日額度用盡時收到明確錯誤（含今日剩餘額度），以便知道額度已用完。
14. 作為登入用戶，我想在留言命中敏感字時看到留言進入待審（僅自己可見），以便知道內容需要人工審核。
14a. 作為登入用戶，我想在一般封鎖／完全封鎖狀態下留言時收到「你的帳號已被限制留言」，以便知道帳號被限制。

### emoji 與三連

15. 作為登入用戶，我想對已發佈留言按 emoji（笑／哭／加油，每人每則每 emoji 一次），以便表達感受。
16. 作為登入用戶，我想取消自己給過的 emoji（再點一次扣回），以便反悔。
17. 用戶可以給自己的留言按 emoji（無限制）。
18. 作為登入用戶，我想一鍵三連（三個 emoji 各給一次，每則限一次），以便快速表達強烈共鳴。
19. 作為登入用戶，我想在用過三連後看到按鈕變灰，以便知道這則已三連過。

### 需求原文對照

20. 作為登入用戶，我想靜音另一用戶（其所有留言含未來的都對我隱藏、可解除、對方無感知），以便過濾不想看到的內容。
21. 作為登入用戶，我想解除靜音，以便恢復看到該用戶的留言。
22. 作為登入用戶，我想在完全封鎖的用戶視角下完全看不到評論區，以便（產品面）完全封鎖是徹底隔離。

## 控制台

### 登入與權限

23. 作為操作員，我想用內部授權系統登入控制台，以便使用全部管理功能。
24. 作為操作員，登入即擁有全部功能（單一權限），以便不需要權限管理。

### 搜尋

25. 作為操作員，我想用關鍵字搜尋所有評論，以便找到特定內容。
26. 作為操作員，我想用時間範圍搜尋評論，以便縮小範圍。
27. 作為操作員，我想用文章 key 搜尋評論，以便處理特定文章的留言。
28. 作為操作員，我想按狀態篩選（待審／已發佈／已刪），以便分別處理不同狀態的留言。
28a. 作為操作員，我想在搜尋結果中直接刪除留言，以便快速處理違規內容。
28b. 作為操作員，我想搜尋用戶（會員 ID 為主、暱稱為輔），以便從用戶出發管理。
28c. 作為操作員，我想查看用戶的留言數據（總數、狀態分佈、近 30 天每日量、最近留言時間、帳號狀態），以便評估是否封鎖。

### 審核

29. 作為操作員，我想看待審列表並批准或拒絕，以便完成人審。
30. 作為操作員，我想管理自訂敏感字（加入／移除，同步到內容審核服務），以便補充機審詞庫。
31. 作為操作員，我想查看審計紀錄（誰在何時刪了哪則、封了誰、敏感字異動），以便追溯操作。

### 封鎖與系統管理

32. 作為操作員，我想對用戶施加一般封鎖（可看、不能留言），以便限制輕微違規者。
33. 作為操作員，我想對用戶施加完全封鎖（不能看、不能留言），以便隔離嚴重違規者。
34. 作為操作員，我想手動解封用戶，以便修正誤封。
35. 作為操作員，我想設定全域留言間隔，以便控制留言頻率。
36. 作為操作員，我想設定全域每日留言上限，以便控制留言總量。
37. 作為操作員，我想查看封鎖狀態（一般／完全／正常），以便掌握用戶狀態。

### 行動場景

38. 作為操作員，我想在手機瀏覽器使用控制台（響應式網頁，免裝 App），以便通勤時找不到桌面電腦也能操作。
39. 作為操作員，我想在手機上以一指完成待審留言的批准／拒絕（審核流程以行動體驗為第一優先），以便隨時隨地清待審佇列。
40. 作為操作員，我想在手機上使用搜尋、封鎖、系統管理等功能（響應式可用、不追求行動最佳化），以便不在電腦前也能處理急事。

## Out of Scope（v1 不做）

- 置頂留言、官方／認證標籤、單篇文章關閉留言
- 通知（回覆通知、審核結果通知）
- 檢舉機制
- 用戶自刪／自編輯留言
- 熱門排序、熱門 emoji 排序
- 嵌入式 widget／SDK（API 優先，各端自建 UI）
- 操作員帳號管理（沿用內部授權系統）
- 誤刪復原（審計留痕，無還原按鈕）
- 即時推送（他人新留言需重新整理）
- 針對個別用戶覆寫間隔／額度
- 待審留言超時自動批准／自動拒絕（留言等待人審，行動版控制台即為延遲解法）
- 控制台原生 App／PWA（響應式網頁已覆蓋行動場景）

## Implementation Decisions

- 兩層結構＋分支內扁平（@ 對象）；主評論最新在前、分支內最舊在前；cursor 分頁；無限捲動（主列表與分支內皆是）
- 文章 key＝呼叫方提供的任意字串（建議 UUID），評論系統不管理文章
- emoji 固定 3 個（笑／哭／加油）；每 emoji 每人每則一次、可取消；三連＝三個全給的快捷、每則一次；只顯示數字不顯示誰按
- 靜音：用戶級、可解除、被靜音者零感知；顯示會員暱稱＋頭像
- 未登入完全不可見（ADR-0003）
- 用戶不可刪不可編自己的留言（ADR-0002）
- 機審採網易雲盾 SaaS，自訂詞同步到雲盾自訂詞庫（ADR-0001，整合細節待補）
- 先審後發；操作員刪主評論→留「已刪除」佔位、回覆保留
- 封鎖：無期限、可手動解封；兩種模式都不隱藏既有留言（ADR-0004）；被拒時回明確訊息
- 額度：送出即計（待審、被拒都算）；間隔從上次送出起算；日界 UTC+8
- 留言內容：純文字、上限 1000 字、允許換行、URL 當普通文字
- 控制台搜尋：關鍵字／時間／文章 key／狀態；搜尋結果可直接刪；用戶搜尋以會員 ID 為主、暱稱為輔（會員系統提供查詢介面）
- 審計紀錄：刪除／封鎖／敏感字異動記操作人＋時間；UI 只做列表
- 前端會員系統與控制台內部授權是兩套獨立系統；操作員帳號沿用內部授權系統
- 控制台為響應式網頁：手機瀏覽器完整可用，審核（待審批准／拒絕）以行動體驗為第一優先設計，其餘功能響應式可用即可
