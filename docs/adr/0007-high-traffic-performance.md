# 高流量場景的效能策略

HK01 是高流量媒體，文章頁的評論列表是讀多寫少的高頻查詢。單靠 PostgreSQL 主庫扛不住尖峰讀取。策略：

- **Redis 快取**：熱門文章的主評論列表（第一頁）與計數快取在 Redis，TTL 短（例如 30 秒），寫入時失效。批次取文章評論的回應也快取。
- **讀寫分離**：列表查詢走 PG 讀副本，寫入走主庫。
- **批次取文章評論**：單次請求最多 N 篇文章、每篇最多回傳頭 M 則主評論＋總數，防止一次拉太多。N 與 M 由系統設定，預設 N=20、M=3。
- **emoji 計數快取**：各 emoji 的數字快取在 Redis，非每次 COUNT 查詢。
